# Architecture

The behaviour is specified in [SPEC.md](SPEC.md); the wire protocol in [PROTOCOL.md](PROTOCOL.md); the models in [MODELS.md](MODELS.md). This page is a map of the code.

```
 hold fn ──▶ desktop app (Tauri: Rust + React)
             HandyKeys ─▶ coordinator (300 ms rule) ─▶ recorder ─▶ live chunker (pieces cut at pauses, previous-chunk context)
                                                                      │  transcribe.cpp + Edda (text-only windows)
                                                                      ▼
             punctuation (Ekko PnC, ONNX Runtime) ─▶ filler words ─▶ replacements ─▶ AI cleanup (optional, per chunk)
                                                                      ▼
             output order (one at a time) ─▶ paste or private clipboard ─▶ pill / notification ─▶ history

 phone app (PWA / iOS shell) ──encrypted 200 ms PCM frames──▶ relay (Worker + Durable Object per room) ──▶ desktop relay client
                                                                                                        └▶ side live stream ─▶ same text steps ─▶ clipboard + notification
```

## Desktop (`src-tauri/`, `src/`)

The desktop app has a core (audio, models, shortcuts, paste, history, tray) and WalkieTalkey's modules beside it (DESK-05). The core calls in through a few hooks marked `WalkieTalkey`:

| Hook in the core                             | WalkieTalkey module                                                                                                                                            | What                                                                                                                                                                                                             |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib.rs` `run`, `initialize_core_logic`, CLI | `walkietalkey::{early_init, startup}`, `bench`, `relay::headless`                                                                                              | managed settings, model loaded at start, relay, updates, notifications; `--live` bench and `--phone-receive` e2e mode                                                                                            |
| `settings::get_settings`                     | `walkietalkey::store::overlay_handy`                                                                                                                           | managed values win (DESK-101)                                                                                                                                                                                    |
| `transcription_coordinator`                  | `Discard`, `ForceStop` effects                                                                                                                                 | short holds dropped, 5-minute limit                                                                                                                                                                              |
| `actions.rs` start/stop                      | `walkietalkey::{keys, limits, dictation, pill, sequence}`                                                                                                      | reveal after 300 ms, fn shortcuts cancel, output in order                                                                                                                                                        |
| `managers/transcription`                     | `audio_toolkit::chunking::ChunkPlan::LIVE_DA`, `pipeline::da::context`, `walkietalkey::{cleanup::key_chunk_observer, punctuation::apply, vocabulary::for_run}` | 10-18 s chunks (Edda: `LIVE_SEGMENTS`, a piece per pause with 1.5 s of speech on each side, run 5), context prompts, text-only windows, cleanup per chunk, Ekko PnC before filler removal, Ord within 150 tokens |
| `managers/model`                             | `walkietalkey::models::company_mirror`                                                                                                                         | `ModelBaseUrl` downloads                                                                                                                                                                                         |
| `catalog`                                    | `walkietalkey::catalog` (`catalog.json`)                                                                                                                       | Edda and Ekko as an overlay on the model catalog, ranking by hardware                                                                                                                                            |
| `clipboard.rs`                               | `walkietalkey::clipboard::write_private`                                                                                                                       | clipboard that stays on this computer                                                                                                                                                                            |
| `managers/audio`, `CaptureSink` raw tap      | `walkietalkey::mic::{guard, start_take, seal_take, finish_take, silent_take}`                                                                                  | silent microphone notice and probe, no system audio (DESK-59)                                                                                                                                                    |
| `lib.rs` single-instance handoff (run 6)     | `walkietalkey::versions::{use_model_arg, use_model_running, use_model_offline}`: `--use-model <id>` from `wt-train use` (DESK-36)                              |
| `lib.rs` single-instance handoff             | `walkietalkey::relay::training::{start, session_arg, NOT_RUNNING_EXIT}`                                                                                        | a `wt-train record` session handed to the running app (run 5)                                                                                                                                                    |
| `tray.rs`, `lib.rs` menu events              | `walkietalkey::tray`                                                                                                                                           | Seneste, Par en telefon, Sæt på pause, Genstart nu, pulse                                                                                                                                                        |

Our own modules (`src-tauri/src/walkietalkey/`, `src-tauri/src/pipeline/da/`):

- `relay/`: the room connection (`crates/wt-relay-client`), pairing QR, phone dictations with their own live decode, key store (keys in the secret store, never the macOS keychain; room and counters beside them), headless e2e mode, and `relay/training` (DESK-65): the workbench's training takes, which the event loop hands over before any dictation code sees them.
- `cleanup/`: modes, markers, guardrails, the editor prompt, providers with pooled warm connections, the chunk-by-chunk engine.
- `settings.rs`, `managed.rs`, `store.rs`: WalkieTalkey settings and the Appendix B overlay.
- `history.rs`, `output.rs`, `dictation.rs`, `notify.rs`, `updates.rs`, `models.rs`, `speed.rs`, `presence.rs`, `secrets.rs`.
- `mic/`: the silent microphone (DESK-59): the level detector on the raw input, the probe that suggests a working input, and the guard that keeps every input stream a microphone (cpal on macOS would otherwise record the system audio from a device without input channels).

## Phone, relay, site

- `phone/`: the PWA (Vite + React), on `@walkietalkey/protocol` and `@walkietalkey/ui`.
- `ios/`: the SwiftUI shell that serves the phone build from bundled files through `WKURLSchemeHandler`.
- `relay/`: Cloudflare Worker and one SQLite-backed Durable Object per room (hibernation, batching, one alarm).
- `site/`: Astro with React islands, static, no cookies or analytics.
- `packages/ui/`: the design system as typed React components and tokens.

## Fine-tuning workbench (`training/`)

Python (uv, PyTorch with MPS, Transformers, PEFT), separate from the app: one command, `wt-train`, with a step per module in `training/wt_train/` (plan, record, fetch, build, train, eval, export, use, smoke, ui, report, pilot, check, card, and run 9's studio). The sentences and the spelling conventions for English developer terms are in `training/data/`; recordings stay in `training/data/recordings/` (git-ignored) and everything large in the git-ignored work folder. Evaluation reuses the accuracy job's normaliser and WER (`models/eval/wt_eval`) and scores a GGUF through the app's own pipeline (`walkietalkey --transcribe-list`). An exported fine-tune is installed in the app's models folder as `edda-ft-<slug>-v<N>.gguf` with a sidecar `<id>.json`, and registered as version N of `edda-da` in the MLflow registry (`wt_train/versions.py`, run 6); the app decodes ids starting with `edda-` like Edda (`walkietalkey::catalog::decodes_by_segment`), lists the versions in Indstillinger › Model (`walkietalkey::versions`), and `wt-train use <N|edda>` switches it through `walkietalkey --use-model` (DESK-36). Every MLflow run is tagged `wt.change`: `pipeline` (the app around the model) or `model` (the weights).

Recording (run 5) goes through the app, so a clip is what the model hears:

```
wt-train record (127.0.0.1 page + API) ◀── HTTP, bearer token ── desktop relay/training ──training_prompt──▶ phone training screen
        │ checks, saves                                             ▲   (connects out only)        ◀──audio_start_training + chunks── (dictation capture)
        ▼                                                           └── Mac takes: AudioRecordingManager, no VAD
recordings/<condition>/<id>.wav + .txt + .json
```

`wt-train plan` first deals every sentence a split (`wt_train/splits.py`: deterministic and stratified, so every term of `spelling.yaml` has at least 2 test and 1 validation sentences and the kinds keep their shares in each split; held-out terms, `data.held_out_terms`, go to test only and are scored as unseen), recorded in `training/data/splits.csv` with its parameters in `split.yaml`; a sentence with a take keeps its split for good. It then gives every sentence one condition (phone whispered, phone normal, Mac normal, Mac whispered; the shares are `training/data/mix.yaml`, 40/40/20/0 unless the owner sets `--mix`, and hold within each split; `training/data/plan.csv`). The first `wt-train eval --dataset test` freezes the test set in `training/data/test-lock.json` (sentence ids and the takes' audio hashes; `wt_train/testset.py`): from then on test holds exactly those sentences, a change to them stops `wt-train build` and the evaluation, and every evaluation on test is logged in `<work>/test-uses.jsonl`. The owner's own words and sentences live in the git-ignored `training/data/local/` (`wt_train/local.py`): his words count as terms, and his sentences are recorded and trained on, never tested. `wt-train record --condition <c>` hands its session to the running app with `walkietalkey --training-session http://127.0.0.1:<port>/app/v1#<token>`; the app long-polls the recorder for prompts and Mac start/stop, sends each prompt to the phone (PRIV-05), and uploads every take as the 16 kHz audio received, before VAD. The recorder checks level, clipping and silence with limits for whispers, saves the take with its metadata, keeps every replaced take, and moves on. The exam (`training/data/exam.yaml`, six long paragraphs read once per condition) is evaluated through the app's live path and never trained on; the dataset builder's leakage check keeps it, and FLEURS test, out of every split. `wt-train eval` reports per condition (`wt_train/per_condition.py`).

Every train, eval and export run is tracked in MLflow (`wt_train/tracking.py`), in the git-ignored work folder (`<work>/mlflow`: a SQLite store and an artifact folder), with MLflow's telemetry switched off: the config, the git commit, the dataset fingerprint per split and condition, the loss of every step, validation every epoch, every eval metric overall and per condition, the FLEURS regression, and the files (loss plot, per-term table, side-by-side transcripts). `wt-train ui` opens MLflow's UI on 127.0.0.1 after adding `training/results.csv` rows as baseline runs; `wt-train card <run>` writes `training/journal/<date>-<run>.md` (`wt_train/journal.py`) with the numbers, the plots, the config diff against the previous run and four empty headings for the owner.

Run 7, before the owner records hours: `wt-train report <run>` (`wt_train/report.py`) turns an evaluation into one self-contained HTML page (WER and CER with 95 % intervals, per condition, substitutions, deletions and insertions, per English term, the 25 worst clips with audio and a word diff from `wt_train/align.py`, built with `wt_train/htmlpage.py`), `--vs` compares two runs with a paired interval, and every page is attached to its MLflow run (`wt-train eval` writes its own). `wt-train pilot record --setup <name>` (`wt_train/pilot.py`) reads the 12 sentences of `training/data/pilot.csv` through the recorder for any setup (a name starting with `iphone`, `phone` or `android` on the phone, any other on the Mac; `whisper` in the name sets the style), into the git-ignored `training/data/pilot/`, which the dataset builder never reads and its leakage check refuses; `wt-train pilot report` compares the setups with base Edda through the installed app's batch path, with the audio measured by `wt_train/audiostats.py`, and logs a `pilot` run (change `data`). `wt-train check` (`wt_train/check.py`) sums up the latest session, pilot or real, in at most 25 lines. `wt-train fetch --overlap` shows that FLEURS test shares nothing with FLEURS train, the split Edda was trained on (docs/MODELS.md).

Run 9, Værkstedet: `wt-train studio` (`wt_train/studio/`) is the workbench as a small local app for the owner, a developer tool that is not part of the WalkieTalkey app users download. A Python server on 127.0.0.1 (stdlib, like the recorder, with its Host, origin and token guards) serves a React page built from `training/studio/` (Vite, the design system's light theme) and the page's JSON API (`training/studio/API.md`), and it is also the recorder the app connects to: the same `/app/v1` API, so a session starts, pauses and resumes from the page, and the phone switches into its training screen only while a Værkstedet session asks for it. Each take is checked as it arrives (the recorder's checks, the audio measures of `wt-train check`, and what base Edda heard through the app's headless batch, in a background worker); a take that fails goes back in the queue by itself, and its review (`approved` or `redo`, by the check or the owner) is kept in the take's metadata, so the dataset builder leaves out a take marked for a new one. The other screens drive the existing steps as child processes (train with `--progress` and `caffeinate -i -w`, export, pilot report, report) and read MLflow, the versions, the journal pages and the splits. "WalkieTalkey Værksted.app" in `~/Applications` (`training/studio/launcher/`, built by `wt-train studio --install-app`) starts the server, opens the page and stops the server on quit; the server also stops when the launcher is gone (`--parent-pid`).

Run 11, learning by running it: five Jupyter notebooks in `training/notebooks/` (01 the sound and Edda's 128 × 3000 log-Mel input, 02 Edda inside, 03 measuring, 04 LoRA, 05 error analysis) run in the workbench's own environment (the default `notebooks` dependency group: ipykernel, jiwer, nbformat, nbclient), with the code in their cells and only one-line Danish headings around it; they are committed without outputs, and `training/tests/test_notebooks.py` checks their shape everywhere and runs them on demand (`WT_RUN_NOTEBOOKS=1`). Værkstedet's Lær det screen (`wt_train/studio/learn.py`) lists them from their metadata and opens a working copy in `<work>/notebooks/` in VS Code (by bundle id, with `training/` as the workspace so its `.venv` is the kernel), so the owner's runs never change the repository. Every tracked run carries the WER normaliser's version (`wt_train/normaliser.py`: a hash of `models/eval/wt_eval/normalize.py` and `danish_numbers.py` mapped to a number); runs from before the tag are classified by the day they were measured, and Evaluering groups runs by it.

Run 12 in Værkstedet: "Dine egne ord" (`wt_train/ownwords.py`, pure and unit-tested, and `wt_train/studio/words.py`) reads the app's dictation history (`history.db` beside its models folder, SQLite `mode=ro`, never written or copied), finds the English-looking words and phrases that `spelling.yaml` does not cover (a Danish vocabulary from the plain sentences, FLEURS' transcripts and a built-in list rules out Danish; letter, case and ending cues find English; Danish endings fold into the English stem) and lists them by how often he said them; no sentence from the history is shown, stored or logged, and a word only travels in a POST body. The ticked words go to the git-ignored `training/data/local/own-words.yaml` and his own sentences to `training/data/local/sentences.csv` (`paths.LOCAL`, `WT_LOCAL_DIR`). The mix (`wt_train/studio/mix.py`) is set on the recording screen: a preview runs `plan.prepare` without writing, dealing again is exactly `wt-train plan --mix` (the split record first, then the plan), and each condition's recording time is the sentences left times the owner's median pace from his takes' `recorded_at` (the pilot's medians until he has enough). Evaluering (`wt_train/studio/measure.py`) measures a training run or Edda on the validation as a job; the test set is a separate action behind a confirm (`WT_TEST_USE_SOURCE=studio`), every use of it is listed from `<work>/test-uses.jsonl` with the lock in `training/data/test-lock.json`, a test result is marked as test, and the comparison offers validation results first.
