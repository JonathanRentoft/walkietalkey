# Privacy

The user-facing privacy policy is the website's Danish page `/privatliv` (`site/src/pages/privatliv.astro`, PRIV-02). This document is the engineering view of the same facts (spec section 12) and of how the code keeps them true.

## What data exists where

| Data                               | Where                                                                                        | How long                                     | Who can read it                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------- |
| Audio from the key                 | computer memory                                                                              | until transcribed                            | the user                                      |
| Audio from the phone               | phone memory; encrypted in transit; encrypted in the relay buffer if the computer is offline | until transcribed; buffer at most 10 minutes | the user's devices only                       |
| Text                               | history on the computer it was dictated to; sent to no other device (training: PRIV-05)      | per retention setting (default 14 days)      | the user                                      |
| Training sentences (run 5)         | computer to phone, end-to-end encrypted, only during a `wt-train record` session             | while the session runs                       | the user's devices only                       |
| Training recordings (run 5)        | `training/data/recordings/` on the owner's computer (not in the repository)                  | until the owner deletes them                 | the owner                                     |
| Text sent to AI cleanup            | the provider the user chose                                                                  | per that provider's terms                    | the provider                                  |
| Device public keys, room ids       | relay                                                                                        | until removed or 90 days unused              | the relay operator (meaningless on their own) |
| IP addresses, connection times     | Cloudflare, as processor for the relay operator                                              | Cloudflare's standard retention              | the relay operator                            |
| Website visits and phone app files | Cloudflare Pages (or the company's `PhoneAppUrl`)                                            | Cloudflare's standard logs; no analytics     | the site operator                             |
| Update checks                      | GitHub (release files and update manifests)                                                  | GitHub's retention                           | GitHub: IP address and app version            |
| Model downloads                    | our GitHub release `models-v1`, or the company's `ModelBaseUrl`                              | their retention                              | GitHub: IP address                            |
| Shared word list                   | the company's `VocabularySource` server                                                      | the company's rules                          | the company                                   |

## How the code keeps it true

- **No telemetry** (PRIV-01): the app, the phone app and the website send no analytics, crash reports or usage data. A crash can only be reported by the user copying a report into a GitHub issue themselves.
- **Audio is not stored** (DESK-92): neither key dictations nor phone dictations keep a recording unless "Gem lyd til fejlfinding" is on. Then the computer keeps both (a phone dictation as it arrived, 16 kHz mono) next to the history item, for at most 7 days (`keep_phone_audio` in `src-tauri/src/walkietalkey/relay/mod.rs`; the 7-day sweep in `src-tauri/src/walkietalkey/history.rs`). The phone keeps audio in memory only (PHONE-33).
- **The phone's warm microphone** (PHONE-30, run 2): while the phone app is open, visible and paired, its microphone stays open so a dictation keeps its first syllable; iOS shows its microphone indicator meanwhile. Between dictations only the newest 300 ms are kept, in a ring buffer in memory that is overwritten all the time; at button-down they become the start of the dictation, so a dictation includes up to 0.3 s from just before the press. The 300 ms are measured on the clock: each batch from the worklet carries the time it arrived, and at button-down only what was captured in the last 300 ms is used, so an audio interruption that suspends the AudioContext without ending the track can never put older audio in front of a dictation. Nothing else is sent, and the microphone closes when the app goes to the background, after 3 minutes without a dictation or a touch, and when no computer is paired (`phone/src/audio/capture.ts`, `phone/src/core/controller.ts`).
- **The relay cannot read anything** (spec 8, 9): it routes binary frames by their plaintext header; payloads are AES-256-GCM with per-direction keys that never leave the two devices. It logs only hashed room ids, close codes and counts (RELAY-13). Dictated text never goes back to the phone (DESK-64).
- **Training sentences** (PRIV-05, run 5): the one text a computer ever sends a phone. Only while the owner runs `wt-train record` (the fine-tuning workbench), the app sends the session's phone the sentence to read as a `training_prompt`, inside the end-to-end encryption, and only sentences from the recorder's list (`training/data/sentences.csv` or the exam); `training_end` returns the phone to normal. The recorder listens on 127.0.0.1 only; the app connects out to it with a per-session token and opens no socket of its own (DESK-65). Training takes go to the recorder on the same computer (`training/data/recordings/`, git-ignored, never uploaded) and are never transcribed, pasted or kept in history (`src-tauri/src/walkietalkey/relay/training.rs`, `phone/src/training/`, `training/wt_train/recorder/`).
- **The clipboard stays on this computer** (DESK-54): on macOS the text is written current-host-only, so Universal Clipboard does not send it to other Apple devices; on Windows it carries the formats that keep it out of Clipboard History and Cloud Clipboard. "Del med mine andre enheder" turns this off.
- **AI cleanup is off by default** (PRIV-04, DESK-80). When it is on, only the text (never audio) goes to the one provider the user chose, with the user's key from the computer's secret store, after the consent text "Teksten (ikke lyden) sendes til <udbyder>, hver gang du dikterer." Each item shows exactly what was sent ("Vis hvad der blev sendt").
- **History at rest** (DESK-94): the history database is in the app data folder. It is encrypted at rest only if the computer's disk encryption (FileVault, BitLocker) is on.
- **Keys** (SEC-09, SEC-10, SEC-11): device keys and pair keys live on the Mac in a private folder only WalkieTalkey writes (excluded from Time Machine, bound to that Mac; never the keychain since v0.2.0), on Windows in Credential Manager (local machine, never roaming); the phone's keys are non-extractable WebCrypto keys.
